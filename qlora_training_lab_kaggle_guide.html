Build a Reusable QLoRA Training Lab on Kaggle

Goal: profile the GPU, capture untuned baseline responses, normalize different dataset schemas, train a 4-bit NF4 QLoRA adapter, compare outputs, and optionally publish the adapter to Hugging Face Hub.

Run cells from top to bottom. Kaggle GPU availability and package compatibility can change. If installation changes core libraries, restart the session and rerun the notebook from the beginning.

Step 3 — Load the untuned model and capture a baseline

A baseline means responses generated by the base model *before* fine-tuning. Load the tokenizer and 4-bit quantized model first, then run fixed prompts and save the results to baseline.json. This JSON is a data artifact, not a Python script.

Code cell 5
from pathlib import Path
import json
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig

MODEL_ID = "Qwen/Qwen3-1.7B"
OUTPUT_DIR = Path("/kaggle/working/qwen3-1.7b-capybara-qlora")
BASELINE_PATH = Path("/kaggle/working/baseline.json")

PROMPTS = [
    "Write a three-bullet checklist for reviewing a pull request.",
    "Explain gradient accumulation in one short paragraph.",
]

quantization_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_use_double_quant=True,
    bnb_4bit_compute_dtype=compute_dtype,
)

tokenizer = AutoTokenizer.from_pretrained(MODEL_ID)
if tokenizer.pad_token is None:
    tokenizer.pad_token = tokenizer.eos_token

model = AutoModelForCausalLM.from_pretrained(
    MODEL_ID,
    quantization_config=quantization_config,
    torch_dtype=compute_dtype,
    device_map={"": 0},
)
print(f"Loaded {MODEL_ID}")
print(f"Model memory footprint: {model.get_memory_footprint() / (1024**3):.2f} GiB")

Generate the two untuned responses

We use the same prompts and generation settings later for the fine-tuned adapter. Sampling can still produce variation, so treat this as a practical comparison rather than a perfectly deterministic benchmark.

Code cell 6
model.eval()
baseline_responses = []

for prompt in PROMPTS:
    messages = [{"role": "user", "content": prompt}]
    formatted = tokenizer.apply_chat_template(
        messages,
        tokenize=False,
        add_generation_prompt=True,
        enable_thinking=False,
    )
    inputs = tokenizer(formatted, return_tensors="pt").to("cuda:0")
    with torch.no_grad():
        generated = model.generate(
            **inputs,
            max_new_tokens=96,
            do_sample=False,
            pad_token_id=tokenizer.pad_token_id,
        )
    new_tokens = generated[0][inputs["input_ids"].shape[1]:]
    response = tokenizer.decode(new_tokens, skip_special_tokens=True).strip()
    baseline_responses.append({"prompt": prompt, "response": response})
    print(f"\nPrompt: {prompt}\nBaseline: {response}\n")

baseline = {
    "model_id": MODEL_ID,
    "compute_dtype": str(compute_dtype),
    "responses": baseline_responses,
}
BASELINE_PATH.write_text(json.dumps(baseline, indent=2), encoding="utf-8")
print("Saved baseline to:", BASELINE_PATH)

Training datasets do not all store conversations the same way. The following fixtures show three common layouts. First, deliberately try a rigid validator that accepts only the messages field.

def require_messages(example):
    if "messages" not in example:
        raise ValueError(f"Expected a messages field; received keys {sorted(example.keys())}")
    return example["messages"]

for name, fixture in FIXTURES.items():

The validator accepts only the conversational fixture. The reusable pipeline should normalize supported source formats into a single canonical contract: a non-empty list of dictionaries containing role and content.

Step 5 — Load and normalize training data

This notebook uses trl-lib/Capybara as the source dataset, matching the article's intended exercise. Dataset schemas can change, so inspect a sample before training. The normalizer below handles the three demonstrated layouts and raises a clear error for unsupported rows rather than silently discarding them.

Code cell 10
from datasets import load_dataset

DATASET_ID = "trl-lib/Capybara"

print(raw_dataset)

print("First training example:")
print(raw_dataset["train"][0])

Define the canonical message normalizer

For records with a messages list, preserve the role/content structure. For prompt-completion or instruction-input-output records, build a user message and an assistant response. If the real dataset uses a different schema, inspect the printed example and adjust the function explicitly.

Code cell 11
def normalize_record(example):
    if isinstance(example.get("messages"), list):
        messages = example["messages"]
    elif "prompt" in example and "completion" in example:
        messages = [
            {"role": "user", "content": str(example["prompt"])},
            {"role": "assistant", "content": str(example["completion"])},
        ]
    elif "instruction" in example and "output" in example:
        user_text = str(example["instruction"])
        extra_input = example.get("input")
        if extra_input not in (None, ""):
            user_text += "\n\nInput:\n" + str(extra_input)
        messages = [
            {"role": "user", "content": user_text},
            {"role": "assistant", "content": str(example["output"])},
        ]
    else:
        raise ValueError(f"Unsupported dataset schema. Keys: {sorted(example.keys())}")

    normalized = []
    for item in messages:
        if not isinstance(item, dict) or "role" not in item or "content" not in item:
            raise ValueError("Each message must be a dict with 'role' and 'content'.")
        normalized.append({"role": str(item["role"]), "content": str(item["content"])})

    if not normalized:
        raise ValueError("Message list cannot be empty.")
    return {"messages": normalized}

# Validate the three fixture layouts.
for name, fixture in FIXTURES.items():
    print(name, "->", normalize_record(fixture))

Apply normalization to the dataset

This cell reports failures with a sample of the original row. If it fails, do not guess at the schema: inspect the sample from the previous cell and update normalize_record to match the actual dataset.

Code cell 12
train_split = raw_dataset["train"]
print("Training rows:", len(train_split))
print("Raw columns:", train_split.column_names)

normalized_rows = []

if errors:

print("Example normalized row:", normalized_rows[0])

Step 6 — Prepare the QLoRA model and training data

We will keep the quantized base weights frozen and train a LoRA adapter. The example is intentionally short for a Kaggle lab, not a production-quality training recipe. The number of rows and steps can be increased after the first run succeeds.

Code cell 13
from datasets import Dataset
from peft import LoraConfig, prepare_model_for_kbit_training
from transformers import TrainingArguments
from trl import SFTTrainer

# Start with a small subset to validate the complete pipeline before a longer run.
MAX_TRAIN_ROWS = min(500, len(normalized_rows))
MAX_STEPS = 30

train_rows = normalized_rows[:MAX_TRAIN_ROWS]
if len(train_rows) < 2:
    raise ValueError("Not enough normalized rows to train. Check the dataset and schema mapping.")

# Render each conversation into the model's expected text format.
def render_messages(example):
    text_value = tokenizer.apply_chat_template(
        example["messages"],
        tokenize=False,
        add_generation_prompt=False,
    )
    return {"text": text_value}

train_dataset = Dataset.from_list(train_rows).map(render_messages)
print(train_dataset)
print(train_dataset[0]["text"][:1000])

Attach the LoRA adapter and configure training

If a Transformers/TRL API error appears here, capture the complete traceback and installed versions. Training APIs can change between releases; don't change multiple package versions blindly.

Code cell 14
model.config.use_cache = False
model = prepare_model_for_kbit_training(model)

lora_config = LoraConfig(
    r=16,
    lora_alpha=32,
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM",
    target_modules="all-linear",
)

training_args = TrainingArguments(
    output_dir=str(OUTPUT_DIR),
    per_device_train_batch_size=1,
    gradient_accumulation_steps=8,
    max_steps=MAX_STEPS,
    learning_rate=2e-4,
    logging_steps=5,
    save_steps=MAX_STEPS,
    save_total_limit=1,
    bf16=bf16_supported,
    fp16=not bf16_supported,
    gradient_checkpointing=True,
    optim="paged_adamw_8bit",
    report_to="none",
    evaluation_strategy="no",
)

trainer = SFTTrainer(
    model=model,
    args=training_args,
    train_dataset=train_dataset,
    peft_config=lora_config,
)
print("Trainable parameter summary:")
trainer.model.print_trainable_parameters()

Train the adapter

This cell may take several minutes. Keep the Kaggle session active until training completes. A short run proves the pipeline works; it does not guarantee that responses improve.

Code cell 15
train_result = trainer.train()
trainer.save_model(str(OUTPUT_DIR))
tokenizer.save_pretrained(str(OUTPUT_DIR))

metrics = dict(train_result.metrics)
metrics["train_rows_used"] = len(train_dataset)
metrics["max_steps_configured"] = MAX_STEPS
if torch.cuda.is_available():
    metrics["peak_memory_gib"] = torch.cuda.max_memory_allocated() / (1024**3)

metrics_path = OUTPUT_DIR / "training_metrics.json"
OUTPUT_DIR.mkdir(parents=True, exist_ok=True)
metrics_path.write_text(json.dumps(metrics, indent=2, default=str), encoding="utf-8")
print(json.dumps(metrics, indent=2, default=str))
print("Saved adapter and metrics to:", OUTPUT_DIR)

Troubleshooting checklist

  • **No GPU:** enable a GPU accelerator in Kaggle settings and rerun the hardware profile.
  • **Package import/API errors:** inspect installed versions; restart after package installation and rerun cells from the top.
  • **Out of memory:** use a smaller model, reduce sequence length or batch size, and close other GPU sessions.
  • **Dataset schema error:** inspect the actual sample and explicitly update `normalize_record`; don't silently drop rows.
  • **Hub authentication/publishing error:** rerun `notebook_login()` with a write token and check the repository ID.
  • **Session restarted:** rerun cells in order. Files under `/kaggle/working` may not survive a new session.
  • **Short run doesn't improve answers:** expected; increase data/steps carefully and compare held-out evaluation, not only two example prompts.
